# mmg-go-tournament

Программа для жеребьёвки турнира по Го по системе Мак-Магон.

## Как использовать программу

### Общие сведения

Программа работает в два этапа:
1. **Первый раунд** — жеребьёвка на основе рейтинга и групп Мак-Магон
2. **Последующие раунды** — жеребьёвка на основе очков, коэффициентов Бухгольца и Бергера

### Первый раунд

Для первого раунда используется отдельная программа (step2). На вход подаётся CSV-файл с участниками:

```
Имя,рейтинг
```

Пример:
```csv
Иванов,1800
Петров,1700
Сидоров,1600
Кузнецов,1500
Попов,1400
Смирнов,1300
```

Программа распределяет участников по группам Мак-Магон, присваивает начальные очки и создаёт пары. Результат сохраняется в файл `имя.001.csv`.

### Последующие раунды

Для жеребьёвки второго и последующих раундов:

```bash
cargo run -- --next-round N --base ИМЯ
```

Где:
- `--next-round` (или `-n`) — номер **следующего** раунда (≥ 2)
- `--base` (или `-b`) — базовое имя файла (без расширения и номера тура)

**Пример:**
```bash
# Создать жеребьёвку 2-го тура (читает имя.001.csv, пишет имя.002.csv)
cargo run -- --next-round 2 --base test_players

# Создать жеребьёвку 3-го тура (читает имя.002.csv, пишет имя.003.csv)
cargo run -- --next-round 3 --base test_players
```

### Формат CSV-файла

**Входной файл** (после первого тура):
```
место,original_place,Имя,рейтинг,группа,очки,Бергер,Бухгольц,результаты...
```

Поля:
| Поле | Описание |
|------|----------|
| `место` | Текущая позиция в таблице |
| `original_place` | Стабильный ID игрока (не меняется при сортировке) |
| `Имя` | Имя участника |
| `рейтинг` | Рейтинг Эло/кю |
| `группа` | Группа Мак-Магон |
| `очки` | Сумма очков (Мак-Магон + победы) |
| `Бергер` | Коэффициент Бергера |
| `Бухгольц` | Коэффициент Бухгольца |
| `результаты...` | Результаты по раундам: `N:`, `N:-`, `N:=` |

**Формат результатов:**
- `N:` — победа над игроком с original_place = N
- `N:-` — поражение от игрока с original_place = N
- `N:=` — ничья с игроком с original_place = N
- `X` — пропуск тура (bye)

### Именование файлов

- `имя.csv` → `имя.001.csv` (первый тур)
- `имя.001.csv` → `имя.002.csv` (второй тур)
- `имя.005.csv` → `имя.006.csv` (шестой тур)

### Рабочий процесс

1. После первого тура файл `имя.001.csv` содержит пары, но без результатов
2. После игр заполните результаты: `N:` (победа), `N:-` (поражение), `N:=` (ничья)
3. Запустите `--next-round 3` — программа считает файл `имя.002.csv`, рассчитает коэффициенты, отсортирует и создаст новые пары
4. Повторяйте для каждого тура

## Как работает программа

### Алгоритм жеребьёвки последующих раундов

#### 1. Загрузка и валидация

Программа читает файл предыдущего тура и проверяет:
- Файл существует
- Результаты предыдущего тура присутствуют

#### 2. Расчёт коэффициентов

**Коэффициент Бухгольца** — сумма очков всех соперников, с которыми играл участник:

```
Бухгольц(i) = Σ очки(соперник_j)
```

Независимо от результата встреч.

**Коэффициент Бергера** — сумма очков соперников, у которых участник **выиграл**:

```
Бергер(i) = Σ очки(соперник_j), где участник выиграл у соперник_j
```

#### 3. Сортировка участников

Участники сортируются по убыванию по трём критериям (последовательно):

1. **Очки** — чем больше, тем выше
2. **Бухгольц** — при равных очках, у кого сильнее соперники
3. **Бергер** — при равных Бухгольце, у кого больше побед над сильными

#### 4. Создание пар

Жеребьёвка проходит в два прохода:

**Первый проход** (без повторов):
- Идём по списку сверху вниз
- Для каждого игрока ищем пару с **максимально близкими очками**
- Игроки, уже встречавшиеся друг с другом, **не pairingуются**
- Если все возможные пары с близкими очками уже сыграли — игрок остаётся временно неспаренным

**Второй проход** (если остались неспаренные):
- Неспаренные игроки pairingуются между собой, даже если разница в очках велика или они уже играли

**Пропуск тура (bye):**
- Только **последний игрок** в таблице может остаться без пары
- Ему записывается результат `X`

#### 5. Сохранение результатов

- Обновляется поле `place` (текущая позиция в таблице)
- В результаты дописывается новый раунд с `original_place` соперника
- Файл сохраняется с увеличенным номером тура

### Стабильный ID игрока

Ключевая особенность — разделение `place` и `original_place`:

- **`original_place`** — неизменяемый ID, присваивается при первом импорте. Используется для хранения результатов и поиска соперников.
- **`place`** — текущая позиция в таблице, меняется после каждой сортировки.

Это позволяет корректно отслеживать историю встреч даже когда игроки перемещаются в таблице после пересчёта коэффициентов.
